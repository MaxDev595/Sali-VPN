# Приватность Sali VPN: как устроено и как выкатить

Документ для команды. Публичная версия для клиентов — `apps/web/src/landing/privacy.ru.md` (salivpn.com/privacy).
Правило: всё, что обещает политика, должно быть правдой в коде. Меняете хранение данных — меняйте и политику.

## Что не хранится нигде

| Данные | Где могли бы оказаться | Почему их нет |
|---|---|---|
| Сайты, трафик | VPN-нода | AmneziaWG/WireGuard не логируют; агент хранит только ключи и адреса (`/etc/sali-node/peers.json`) |
| DNS-запросы | нода / Google | свой Unbound на ноде, `log-queries: no`, `verbosity: 0` |
| Настоящий IP клиента | нода, API | на ноде — только в RAM, пока сессия активна; в базе нет такого поля; Fastify-логгер API выключен |
| Время подключений | база | у устройства хранится только **день** последнего использования (`activityDay()` в `devices.service.ts`) |
| Объём трафика пользователя | нода | агент отдаёт только число устройств и load average |

## Что сделано (ветка `privacy-hardening`)

**VPN-ноды** (`infrastructure/vpn-node/install.sh`, агент 2.1.0)
- Изоляция клиентов: `FORWARD -s 10.66.0.0/15 -d 10.66.0.0/15 -j DROP` (оба туннеля).
- Запрет доступа из VPN к частным сетям хостера и метаданным облака (`169.254.169.254` и т. п.).
- Свой DNS-резолвер Unbound на `10.67.0.1` / `10.66.0.1`: без журналов, DNSSEC, QNAME minimisation, защита от DNS-rebinding.
- journald только в RAM (`Storage=volatile`, 32 МБ, хранение 1 день), `/var/log/journal` удалён.
- Агент сообщает `dns: true`, API ставит `VpnServer.privateDns` и отдаёт клиентам DNS ноды. Старым нодам — Quad9 + Cloudflare вместо Google.

**API**
- Отдельный `ENCRYPTION_KEY` для приватных ключей клиентов и ключей агентов (формат `v2:`). При старте API перешифровывает старые записи (`VpnService.resealSecrets`). После этого утечка `JWT_SECRET` не раскрывает ключи VPN.
- `Device.lastActiveAt` округляется до дня.
- Миграция `20261109120000_node_private_dns` (колонка `privateDns`).

**Android**
- Release-сборка подписывается только собственным ключом Sali (`scripts/make-release-key.cmd`), CI берёт его из секретов, проверяет подпись и публикует отпечаток сертификата и SHA-256 APK рядом со сборкой. Без ключа release-сборка останавливается.

**Сайт**
- Новая политика конфиденциальности (RU/EN) с конкретными списками «храним / не храним»; справка «DNS» и «Приватность» обновлена; страница документов умеет таблицы; исправлен email в русской версии (раньше `work\@salivpn.com` превращался в ссылку на Telegram @salivpn).

## Как выкатить (по порядку)

1. **Render:** после пуша блюпринт добавит `ENCRYPTION_KEY` сам. Если не добавил — Render → sali-api → Environment → `ENCRYPTION_KEY` = результат `openssl rand -hex 32`. **Никогда не меняйте и не теряйте его** — сохраните копию в менеджере паролей. В логах после деплоя: `re-encrypted N secret(s) with ENCRYPTION_KEY`.
2. **Каждая нода:** `/addserver <страна>` в боте и вставить команду на той же VPS (повторный запуск безопасен, ключи и пользователи сохраняются). Проверка на ноде:
   ```
   systemctl is-active unbound            # active
   dig @10.67.0.1 example.com +short      # IP-адрес
   iptables -S FORWARD | grep 10.66.0.0/15
   journalctl --header | grep -i storage  # volatile
   ```
   Через ≤15 минут (или после `/nodes`) API отметит `privateDns` и клиенты при следующем подключении получат DNS ноды.
3. **Android-ключ (один раз):** запустить `scripts\make-release-key.cmd`, сохранить папку `%USERPROFILE%\.sali` в надёжное место, добавить 3 секрета в GitHub (Settings → Secrets and variables → Actions), удалить `github-secrets.txt`. Опубликовать отпечаток SHA-256 на сайте.
   ⚠️ Подпись меняется, поэтому приложение, установленное из старых APK, нужно **один раз удалить и поставить заново**. На Android 8+ идентификатор устройства зависит от ключа подписи, так что после переустановки у телефона будет новый Sali ID: если у кого-то уже есть активный код, перенесите подписку через админку.
4. **Сайт:** `npm run deploy:web`.

## Что ещё можно сделать (не входит в эту ветку)

- Генерировать ключ WireGuard на устройстве и отправлять в API только публичный — тогда приватных ключей клиентов не будет даже в зашифрованном виде. Требует доработки Android, Windows и API (переход на сервер с теми же ключами).
- Регулярный отчёт о прозрачности (сколько запросов от госорганов получено) и независимый аудит.
- Автоматическое удаление аккаунтов, неактивных N месяцев.
