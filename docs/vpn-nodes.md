# VPN-серверы (ноды) Sali

Каждый VPN-сервер — обычный VPS с Ubuntu 22.04/24.04. На нём работают:

- **AmneziaWG** (`awg0`, случайный UDP-порт 30000–60000) — WireGuard с маскировкой трафика. Работает там, где обычный WireGuard блокируют (Россия).
- **WireGuard** (`wg0`, UDP 51820) — для старых версий приложений.
- **Агент Sali** (`sali-node-agent`, TCP 8443, HTTPS). Через него API добавляет и отключает пользователей.

Одни и те же пользователи живут сразу в обоих туннелях. Приложение само выбирает протокол заголовком `X-VPN-Protocol: awg`. Приватные ключи клиентов на сервер не попадают: их создаёт API и хранит в базе в зашифрованном виде.

## Добавить сервер (≈5 минут)

1. Купите VPS (Hetzner CX23, Ubuntu 24.04) и откройте консоль от root.
2. В боте Sali (только админ из `ADMIN_TELEGRAM_IDS`):
   ```
   /addserver DE
   /addserver FI Helsinki
   ```
   Бот пришлёт одну команду. Она одноразовая и действует 24 часа.
3. Вставьте команду в консоль сервера. В конце появится «Готово: Sali DE-1 подключён».
4. Первый раз: Render → Environment → `VPN_PROVIDER=nodes`.

Повторный запуск команды на том же сервере безопасен: ключи и пользователи сохраняются.

## Управление из бота

- `/nodes` — список серверов: онлайн, сколько пользователей, кто подключён сейчас, нагрузка.
- `/node_off Sali DE-1` — сервер больше не получает новых пользователей; текущих при следующем подключении перенесёт на другой.
- `/node_on Sali DE-1` — включить обратно.
- `/myid` — показывает ваш Telegram ID для `ADMIN_TELEGRAM_IDS`.

## Надёжность

- Пользователи хранятся в `/etc/sali-node/peers.json` и возвращаются в туннели после перезагрузки или рестарта туннеля. Есть ещё сторожевая проверка раз в 30 секунд.
- Если сервер, к которому привязан пользователь, не отвечает, API при следующем подключении переносит его на живой сервер с теми же ключами.
- Раз в 15 минут API опрашивает все ноды и обновляет их статус и нагрузку.
- Сеть настраивается установщиком: BBR, увеличенные буферы, clamp MSS, у клиентов MTU 1280 (стабильнее в мобильных сетях).

## Защита самого сервера

Установщик запускает `harden.sh` (его можно запускать отдельно, повторно — безопасно):

```
curl -fsSL https://api.salivpn.com/api/v1/nodes/harden.sh | bash
```

- root входит по SSH только по ключам из `infrastructure/vpn-node/admin_keys.pub`, вход по паролю по SSH выключен
  (только если хотя бы один ключ установлен). Веб-консоль Vultr/Hetzner по паролю root работает как запасной вход.
- fail2ban: 5 неудачных попыток входа — бан IP на час.
- обновления безопасности ставятся автоматически.
- Новый администратор: добавьте его публичный ключ строкой в `admin_keys.pub`, задеплойте и запустите `harden.sh` на нодах.
- Вход с ПК: `ssh root@IP` (ключ `%USERPROFILE%\.ssh\id_ed25519` подхватывается сам).

## Диагностика на сервере

```
systemctl status sali-node-agent awg-quick@awg0 wg-quick@wg0
journalctl -u sali-node-agent -n 50
awg show          # пользователи AmneziaWG
```
